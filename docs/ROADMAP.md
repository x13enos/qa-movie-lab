# Backlog — не реализован в MVP

Каждая итерация — отдельный PR, новая версия `API_CONTRACT.md`, запись в `CHANGES.md`, собственные black-box тесты QA. Незавершённые функции не показываются как рабочие UI-кнопки.

- **Iteration 2 — Rating filter:** `min_rating` — необязательное число 0–10; включительная граница. Фильтрация всего набора **до** пагинации, пересчёт totals. При 8 исключить 7.9, включить 8.0 и 8.1. В TMDB — `vote_average.gte` для discover, не фильтрация уже загруженных 20 записей. Некорректные значения → 422.
- **Iteration 3 — Search:** поиск по названию; контракт согласовать отдельно, TMDB `/search/movie`.
- **Iteration 4 — Sorting:** сортировка по рейтингу и дате; контракт согласовать.
- **Iteration 5 — Movie details:** `GET /api/movies/{id}`, включая 404.
- **Iteration 6 — Favorites:** локальные добавление/удаление; БД только по отдельному решению.
- **Iteration 7 — Failure scenarios:** контролируемые внешние ответы/ошибки для black-box testing.
- **Iteration 8 — UI automation:** отдельный этап Playwright, тесты пишет QA.

CI/GitHub Actions — позже, после появления первых QA-тестов. MVP не содержит БД, авторизации, Docker, облачной инфраструктуры и микросервисов.
